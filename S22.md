# Galaxy S22 notes

This project is developed and tested on a Samsung Galaxy S22. The S22 isn't on XREAL's tested list, and it's now on Android 16, which XREAL doesn't support yet. It only works with the glasses because of a few non-default settings. This page records the phone's state, what was changed and why, and how to put it back after a reset.

Commands below use Unity's copy of `adb`:

```sh
ADB=/Applications/Unity/Hub/Editor/6000.6.0f1/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb
```

## Current state (2026-10-20)

| | |
| --- | --- |
| Model | SM-S901W (Canada), CSC XAC (unlocked) |
| Firmware | `S901WVLSAGZH3`: Android 16, One UI 8.0, security patch 2026-08-05 |
| Bootloader | Binary A (10), locked, verified boot green |
| XREAL runtime | Control Glasses `3.1.0.20251118115716` (`com.xreal.glassescontrol`) |
| Also installed | Nebula (`ai.nreal.nebula.universal`), the older XREAL app, which SDK 3.x doesn't use. Older NRSDK test builds (`com.DefaultCompany.XRealTest2*`) |

## Required settings

| Setting | Value | Why |
| --- | --- | --- |
| `secure mirror_built_in_display` | `1` (default `0`) | Stops One UI 8 from putting a DeX desktop on the glasses. Without it, every XREAL app shows black and crashes. See [below](#why-android-16-breaks-xreal) |
| Samsung DeX | Off | Same reason. Don't accept DeX when the glasses connect |
| `com.wssyncmldm`, `com.sec.android.soagent` | Disabled | Blocks Samsung system updates. See [below](#automatic-updates-are-blocked) |
| USB debugging | On | Needed for deploying and logs |

To check all of them at once:

```sh
$ADB shell settings get secure mirror_built_in_display            # expect 1
$ADB shell pm list packages -d | grep -E "wssyncmldm|soagent"     # expect both listed
$ADB shell getprop ro.build.PDA                                   # expect S901WVLSAGZH3
```

## What happened

- **2026-10-07:** set up for this project on **Android 14**. The phone's clock was set to September 2024, which also meant it hadn't been getting updates. Once the clock was corrected, everything worked with Control Glasses 3.1.0.
- **2026-10-18:** the phone updated itself to **Android 16 / One UI 8**. Its restart log shows two install cycles: restarts into recovery, each followed by a `reboot,ota`, between 12:24 and 12:33. The build installed then (`S901WVLSAGZH3`) is the newest one available, so these were most likely the upgrade itself, possibly done in two steps.
- **2026-10-20:** XREAL apps were broken: the glasses went black, the phone screen went black, and apps crashed. Diagnosed and fixed with the mirror setting. A rollback to Android 15 turned out to be impossible. Automatic updates were blocked.

## Why Android 16 breaks XREAL

XREAL's [compatibility page](https://docs.xreal.com/XREALDevices/Compatibility) says: *"Android 16 Compatibility Notice: Compatibility issues are under investigation. Please do not upgrade your development devices to Android 16."* As of 2026-10-20 there's no fix: the newest releases are still SDK 3.1.0 and Control Glasses 3.1.0.

On this phone, the phone's logs show the failure happens in this order:

1. When the glasses connect, One UI 8 treats them as a **desktop display**. It starts Samsung's DeX home screen on them (`com.honeyspace.dexservice.SecondaryLauncher`), which shows briefly in the glasses as a desktop.
2. Control Glasses switches the glasses into 3D side-by-side mode, so they reconnect as a new 3840×1080 display. Android adds a wallpaper, mirroring and its desktop status and navigation bars to that display.
3. Adding those bars crashes Samsung's System UI (`KeyguardDisplayManager … Display.getDisplayId() on a null object reference`). Control Glasses crashes too (`BadTokenException`).
4. Android then **drops the glasses' display**. The display hardware logs `Pluggable display creation failed/aborted. Error -19 'No such device'`.
5. When an XREAL app starts, there's no glasses display (`tryStartFakeActivity failed`). XREAL's runtime crashes while setting up rendering: `SIGSEGV` in `libnr_api.so`, called from `NRSwapchainCreateEx`.

This affects every XREAL app, not just this project.

## The fix: mirror built-in display

```sh
$ADB shell settings put secure mirror_built_in_display 1
```

`mirror_built_in_display` is an Android 16 setting for connected displays:

- `0` (default): a connected display becomes an extended desktop with its own home screen and system bars.
- `1`: a connected display mirrors the phone, which is how Android 14 and 15 behaved. XREAL's runtime can then take the display over for the glasses.

With this set and DeX off, the SDK works again (confirmed 2026-10-20).

- **Persistence:** the value is stored in Android's settings database, so it should survive restarts; it hasn't been tested across a restart yet. A factory reset clears it.
- **Side effects:** monitors and TVs plugged into the phone mirror its screen instead of opening a DeX desktop.
- **Undo:** `$ADB shell settings put secure mirror_built_in_display 0`. This brings the XREAL problem back.

If the black screen comes back, check this value first. A Samsung update, or changing the external display or DeX options in Settings, could reset it.

## Automatic updates are blocked

The two system apps that run Samsung's software updates are disabled for the user:

```sh
$ADB shell pm disable-user --user 0 com.wssyncmldm      # Samsung "Software update" client
$ADB shell pm disable-user --user 0 com.sec.android.soagent  # background update agent
```

Developer options' **Auto system update** is also off (`global ota_disable_automatic_update=1`), but Samsung's updater ignores that switch, so it doesn't block updates on its own.

What this means:

- No Samsung firmware updates, no update restarts, and no Samsung security patches.
- Settings → Software update is missing or doesn't work.
- App updates from Galaxy Store and Play Store, and Google Play system updates, still happen.
- Disabled apps stay disabled across restarts. A factory reset re-enables them.

To allow updates again (expect more One UI changes that may break XREAL):

```sh
$ADB shell pm enable com.wssyncmldm
$ADB shell pm enable com.sec.android.soagent
```

## Why it can't go back to Android 15

Samsung firmware carries a bootloader "binary" revision: the 9th character of the build name, `S901WVLS?…`. The phone permanently refuses firmware with a lower revision than it has already run. Odin fails with an `SW REV CHECK FAIL` error, and no wipe or setting resets this hardware fuse. The S901W's bootloader also can't be unlocked.

| Model | Newest Android 15 build | Its binary | Phone now |
| --- | --- | --- | --- |
| SM-S901W (this phone) | `S901WVLS8FYG7` (Aug 2025) | 8 | **A (10)** |
| SM-S901U1 (US unlocked, same hardware) | `S901U1UES8FYI2` (Sep 2025) | 8 | — |

Binary 9 and A only appeared in Android 16 builds in 2026, so there's no Android 15 firmware this phone will accept. Source: firmware listings on [Samfrew](https://samfrew.com/model/SM-S901W/region/XAC/) and [SamMobile](https://www.sammobile.com/samsung/galaxy-s22/firmware/SM-S901W/XAC/), 2026-10-20. The US carrier model (SM-S901U) wasn't fully checked, but its builds follow the same releases as the U1.

The other ways out are an XREAL **Beam Pro** (XREAL's own host device), or a Samsung flagship that's still on Android 14 or 15 with updates blocked.

## After a factory reset

1. Settings → Developer options: turn on **USB debugging**. Turn **Auto system update** off.
2. Turn **Automatic date and time** on. A wrong clock breaks Play Store downloads and secure connections.
3. Install Control Glasses 3.1.0 and open it once, accepting its permissions (see the [README](README.md#3-prepare-the-phone)).
4. `$ADB shell settings put secure mirror_built_in_display 1`, and keep DeX off.
5. Disable the two update apps (commands [above](#automatic-updates-are-blocked)).
6. Rebuild and install the app. Saved rooms and tagged items are lost with the reset.

## Other quirks

- **Wireless ADB** is needed because the glasses take the phone's only USB-C port. `Tool/wireless-adb.sh` sets it up from a USB connection. TCP mode is lost on every restart.
- **Control Glasses must be opened once** after installing, or Android keeps it in a stopped state and XREAL apps can't find the runtime. Right after reinstalling it, open it again before starting an XREAL app.
- **Without the glasses connected,** XREAL apps start and then close themselves, because there's no runtime session. That's expected.
